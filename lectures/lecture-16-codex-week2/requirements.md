# 강의 요구사항 정의서: 2주차

## 기본 정보

| 항목 | 내용 |
|------|------|
| 강의명 | 에이전트와 함께하는 삶의 전환: 2주차 |
| 주제 | 에이전트 잘 쓰는 방법 |
| 대상 | 비전공자 (30대~60대), 1주차 수강생 |
| 수강 환경 | 대부분 Windows |
| 형식 | 120분, 온라인. 이론 12분, 실습 89분 |
| 실습 도구 | ChatGPT 데스크탑 앱의 **Codex** |
| 실습 자료 | 수강생용 실습지(`worksheet.html`), 강사용 진행표(`runsheet.html`) |

수강 대상의 전제는 [1주차 요구사항](../lecture-15-codex-4weeks/requirements.md)과 같습니다.
터미널, 명령어, 복사·붙여넣기 숙련도, 영어를 전제하지 않습니다.

## 1주차와의 관계

| 구분 | 1주차 | 2주차 |
|------|-------|-------|
| 질문 | 왜 배워야 하는가 | 무엇까지 맡길 수 있는가 |
| 내용 | 사례, 동기, 첫 실행 | 작동 원리, 쓸모 있는 결과물을 만드는 실습 |
| 종료 시점의 상태 | 결과물 파일 한 개 제작 | 연하장, 보고서, 글, 음성을 직접 제작 |

## 학습 목표

1. 에이전트의 구조 설명: LLM, 도구 사용, 반복
2. LLM이 다음 낱말을 예측한다는 원리 설명
3. 요청에 내 상황을 적으면 결과가 달라진다는 사실 확인
4. Computer Use(에이전트의 컴퓨터 조작)의 개념 이해와 경험: 에이전트가 화면을 보면서 마우스와 키보드로 다른 앱을 조작해 결과물을 만드는 과정. 오늘 수업의 핵심
5. 실습마다 에이전트가 어떤 도구를 쓰는지 구분
6. 그림, 웹페이지, 보고서, 글, 음성을 요청해서 받는 경험
7. 만든 웹페이지를 인터넷 주소로 올려 다른 사람과 주고받는 경험
8. 결과에서 고칠 곳을 말로 요청하는 방법 적용
9. 실습마다 잘 쓰는 방법 한 가지를 익히고, 자기 일에 쓸 예 떠올리기
10. 결과를 보면서 고친 내용을 프롬프트로 정리하고, 저장해서 다시 쓰는 과정 경험
11. 프롬프트를 쌓는 일이 개인과 회사의 노하우를 정리하는 일이라는 점 이해
12. 챗봇, 웹·앱 에이전트와 비교해서 내 컴퓨터에 설치한 에이전트의 이점 설명: 내 파일, 내 컴퓨터의 앱과 프로그램, 폴더에 쌓이는 결과물과 프롬프트
13. 휴대폰 에이전트 피클의 쓰임과 쓰기 전에 정할 것 이해 (설치와 사용은 과제)

## 핵심 문장

> 오늘, 에이전트에게 맡길 수 있는 일의 범위를 넓히셨습니다.

## 용어

한 대상에 한 용어만 씁니다.

| 용어 | 뜻 | 쓰지 않는 표현 |
|------|-----|----------------|
| LLM | 대규모 언어 모델. 다음 낱말을 예측하는 모델 | 예측기, 두뇌 |
| 낱말 | LLM이 한 번에 고르는 단위 | 말, 조각, 토큰 |
| 내 상황 | 사용자만 아는 목적, 읽는 사람, 원하는 형식 | 맥락, 전제, 사정 |
| 요청 | 에이전트에게 보내는 문장 | 주문, 명령 |
| 프롬프트 | 다음에 다시 쓰려고 정리해 둔 요청 | 주문서, 레시피 |
| 도구 | 에이전트가 일을 하려고 쓰는 프로그램과 기능 | 무기, 손발 |
| 허용 창 | 에이전트가 다른 앱을 쓰기 전에 묻는 창 | 권한 팝업 |
| 인터넷 주소 | 만든 웹페이지를 다른 사람이 열 수 있는 주소 | URL, 링크 |
| 예약 | 같은 요청을 정한 시각마다 실행하게 하는 설정 | 자동화, 스케줄 |

"LLM은 다음 낱말 예측만 훈련했다"는 말은 하지 않습니다. 기본 훈련 뒤에 지시를 따르도록 하는 추가 훈련이 있습니다. "기본 훈련은 다음 낱말 예측"이라고 말합니다.

"LLM은 문장을 미리 계획하지 않는다"는 말은 하지 않습니다. 한 모델이 운율을 맞춘 시를 쓸 때 줄 끝에 올 낱말을 미리 골라 둔다는 연구가 있습니다([Anthropic, 2025](https://www.anthropic.com/research/tracing-thoughts-language-model)). "한 번에 한 낱말씩 내놓는다"까지만 말합니다.

## 설계 원칙

형식은 1주차 덱(`../lecture-15-codex-4weeks/_build/w1.py`)을 그대로 따릅니다.

- 한 장에 **상징적인 그림 하나 + 문장 하나**. 글을 많이 넣지 않음
- 실습은 쓰임, 결과 화면, 에이전트가 조작하는 것, 요청 문장, 확인과 고치기, 익힌 방법의 순서로 구성
- 실습마다 잘 쓰는 방법 한 가지를 "익힌 방법" 장표에 정리하고, 마무리에서 한 장에 모음
- 뒤 단계의 요청은 앞에서 만든 것을 이름이 아니라 순서로 가리킴("지금까지 만든 그림"). 예시를 바꾸거나 단계를 건너뛰어도 문장이 그대로 통함
- 연하장은 만들기와 인터넷에 올리기를 다른 요청으로 분리. 만든 것을 보고 고친 뒤에 공개
- 보고서와 예약의 요청에는 "인터넷에 올리지는 마"를 포함
- 연하장을 만든 뒤에 "내 프롬프트" 구간을 둠. 품질 기준(고쳐 달라고 한 것) → 반복 → 프롬프트로 정리 → 프롬프트 다듬기(빼기와 업데이트) → 저장 → 다시 쓰기 → 노하우의 순서
- 매일 예약과 쇼츠 영상, 프롬프트 다시 쓰기는 강사의 화면으로 보여 줌
- 실습 예시는 수강생에게 실제로 쓸모 있는 결과물로 구성
- 화면의 요청 문장은 Codex에 실제로 보낸 문장을 사용. 그림판 문장만 예외(리허설 문장의 "Freeform 앱을"을 "그림판을"로 바꿈). 확인한 범위는 발표자 노트의 "리허설"에 기록
- 연하장, 계획 보고서, 블로그 글의 요청 문장에는 내 상황을 적는 줄을 한두 줄씩 포함. 수강생은 이 줄을 자기 상황으로 바꿔 입력
- 요청 문장을 보여 주는 장표마다 에이전트가 쓰는 도구를 "쓰는 도구" 줄에 표시. 리허설에서 실제로 쓴 도구는 발표자 노트에 기록
- 실습마다 꼭 하는 단계와 시간이 남으면 하는 단계를 구분
- 기술 설명은 화면이 아니라 발표자 노트에 작성
- 비유 금지. 표준 기술 용어와 표준 교육 용어 사용
- 터미널 미사용. GUI 앱만 사용
- 만든 페이지가 공개되므로 전화번호, 주소, 주민등록번호는 적지 않도록 안내

빌드 후에는 화면 글자 수 중앙값과 그림이 있는 장표의 비율을 1주차와 비교합니다.

| 측정 항목 | 1주차 | 2주차 |
|-----------|-------|-------|
| 장표 수 | 56장 | 77장 |
| 화면 글자 수 (중앙값) | 34.5자 | 39자 |
| 그림이나 캡처가 있는 장표 | 64% | 47% |
| 아랫줄이 있는 장표 | 14% | 44% |

2주차는 요청 문장을 보여 주는 장표가 14장, 익힌 방법을 정리하는 장표가 5장이어서 그림의 비율이 낮고 아랫줄의 비율이 높습니다. 실습 구간이 시작되는 장표 6장의 아랫줄에는 실습지 링크가 있습니다. 앱 화면의 캡처를 넣을 장표 6장은 아직 없습니다.

## 실습 설계

실습마다 꼭 하는 단계와 시간이 남으면 하는 단계를 나눕니다.

| 실습 | 꼭 하는 단계 | 시간이 남으면 | 익히는 방법 |
|------|--------------|---------------|-------------|
| 1 연하장 | 그림 생성, 연하장 만들기, 인터넷에 올리기, 서로 보내기 | 그림판으로 그리기가 되지 않으면 건너뜀. 고칠 곳 말하기 | 앞에서 만든 것을 가리켜 이어 가기 |
| 2 계획 보고서 | 보고서 한 개, 조건이 들어갔는지 확인 | 고칠 곳 말하기 | 조건을 적어서 계획 바꾸기 |
| 내 프롬프트 | 프롬프트로 정리, 프롬프트 다듬기(빼기와 업데이트), 저장 | 새 채팅에서 다시 쓰기 | 고친 내용을 프롬프트로 남기기 |
| 3 관심 주제 보고서 | 보고서 한 개, 출처 확인 | 매일 예약(수업에서는 강사 시연) | 출처를 요구하고 눌러서 확인하기 |
| 4 블로그 글 | 글 한 편, 겪은 장면 덧붙이기 | | 내가 겪은 장면 덧붙이기 |
| 5 쇼츠 | 인사말 음성 | 그림과 음성을 합친 영상(수업에서는 강사 시연) | 만든 것을 재료로 다시 쓰기 |

이론에서 익히는 방법은 "내 상황 적기"와 "고칠 곳 말하기"입니다.

### 에이전트가 쓰는 도구

화면에는 요청 장표마다 "쓰는 도구" 줄로 적습니다. 아래는 2026-11-27 리허설(Mac)에서 에이전트가 실제로 쓴 도구입니다.

| 단계 | 화면의 표기 | 리허설에서 실제로 쓴 도구 |
|------|-------------|--------------------------|
| 그림판으로 그리기 | 그림판 · 에이전트가 마우스와 키보드를 조작 | Codex의 Computer Use 기능으로 Freeform 앱 조작. PDF로 내보낸 뒤 명령줄 도구(`pdftoppm`)로 PNG 변환 |
| 그림 생성 | Codex의 그림 생성 기능 | Codex에 들어 있는 그림 생성 도구 |
| 연하장 만들기 | 웹페이지 파일 작성 | 파일 작성. 이 요청만으로는 인터넷에 올리려 하지 않음 |
| 인터넷 주소 | Codex의 사이트 기능 | 사이트 만들기와 공개, 앱 안의 브라우저로 열기 |
| 계획 보고서 | 웹 검색 · 웹페이지 파일 작성 | 웹 검색(경주시, 박물관, 숙소의 공식 사이트), 파일 작성 |
| 관심 주제 보고서 | 웹 검색 · 웹페이지 파일 작성 | 웹 검색(다섯 번), 파일 작성 |
| 장면 덧붙이기 | (블로그 글 쓰기와 같음) | 도구를 쓰지 않음 |
| 매일 예약 | Codex의 예약 기능 | Codex의 예약 등록과 삭제 |
| 블로그 글 쓰기 | 없음 · LLM이 글을 직접 작성 | 도구를 쓰지 않음 |
| 음성 만들기 | 컴퓨터의 글 읽어 주기 기능 | Mac의 글 읽어 주기 명령(`say`), 파일 형식 변환 |
| 쇼츠 영상 | 영상 편집 도구 · 에이전트가 직접 작성한 프로그램 | 에이전트가 작성한 파이썬 프로그램(그림 라이브러리 Pillow 사용), 영상 편집 도구 `ffmpeg` |

Windows에서 에이전트가 음성과 영상에 어떤 도구를 쓰는지는 확인하지 못했습니다. 파이썬, Pillow, `ffmpeg`는 Windows에 기본으로 들어 있지 않습니다.

- 연하장 실습은 채팅 하나에서 이어서 진행. 뒤 단계의 요청이 앞 단계에서 만든 그림을 가리킴
- 실습 2~4는 새 채팅에서 시작. 실습 5는 연하장을 만든 채팅으로 돌아가서 진행
- 화면에 나눠 적은 요청의 전체 문장은 `_build/w2.py`의 `SAY`에 있고, 실습지와 진행표가 이 문장을 사용

### 리허설 결과 (2026-11-27)

리허설은 Mac에서 두 가지 방식으로 했습니다. "앱"은 ChatGPT 데스크탑 앱의 Codex 화면이고, "실행 파일"은 앱 화면을 거치지 않고 앱에 들어 있는 Codex 실행 파일을 직접 실행하는 방식입니다. 앱 방식의 시간은 앱 기록에 남은 턴의 길이이고, 실행 파일 방식의 시간은 실행 스크립트가 잰 값입니다.

| 요청 | 방식 | 걸린 시간 | 결과 |
|------|------|-----------|------|
| Freeform 앱을 열어서 눈사람 그리기 | 앱 | 턴 전체 5분 15초 (허용 창 대기 2분 22초, 허용 뒤 2분 54초) | Freeform에서 PDF로 내보내고 PNG로 변환해 저장. 앱 조작의 허용 창 1회 |

| 에이전트가 메일이나 메신저로 직접 보내기 | 미확인. 수업에서는 주소를 채팅창에 올리는 방식 사용 |
| 에이전트가 블로그에 직접 올리기 | 미확인. 수업에서는 글을 복사해 붙여 넣는 데까지 안내 |

## 실습 자료

실습지와 진행표는 `_build/handouts.py`가 덱에서 만든 생성물입니다. 요청 문장, 표, 시각은 덱에서 읽어 옵니다.

덱에는 실습 구간이 시작되는 장표마다 실습지의 해당 절로 가는 링크가 있습니다. 링크는 `w2.py`의 `ws()`가 만들고, 절의 주소(`#card`, `#prompt`, `#plan`, `#topic`, `#blog`, `#shorts`)는 `handouts.py`의 `sec(..., id=)`가 붙입니다. 주소는 덱과 같은 폴더의 `worksheet.html`을 가리키는 상대 경로이므로, Marp 판을 PDF나 PPTX로 변환한 파일에서는 이 링크가 열리지 않습니다.

| 자료 | 대상 | 내용 |
|------|------|------|
| `worksheet.html` | 수강생 | 실습별 요청 문장과 쓰는 도구, 내 상황을 적는 칸, 주의 문구, 확인 항목, 익힌 방법, 수업 뒤에 남는 것, 이번 주 과제 |
| `runsheet.html` | 강사 | 강의 전 준비 목록, Windows에서 확인할 것, 시각별 진행표, 채팅창에 올릴 문장, 막힌 수강생에게 알려줄 문장 |

- 실습지의 칸에는 화면에서 바로 입력합니다. 입력한 내용은 그 기기의 브라우저 저장소(`localStorage`)에만 저장되고 다른 곳으로 전송되지 않습니다.
- 저장소를 쓸 수 없는 브라우저에서는 입력은 되지만 저장되지 않고, 화면에 그 사실을 알립니다.
- 실습지는 인쇄해서 손으로 적어도 됩니다. 인쇄할 때는 입력한 내용이 함께 찍힙니다.

## 성공 기준

- 수강생 전원이 연하장을 만들어 주소를 채팅창에 올림
- 수강생 전원이 보고서 한 개 이상 제작
- "요청한 내용과 다른 결과가 나오는 이유"를 묻는 질문에 "내 상황을 알려주지 않아서"로 답변
- 예약을 만든 수강생 전원이 수업이 끝나기 전에 예약 삭제
